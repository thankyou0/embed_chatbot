Task 2: Badge Component — Semantic Tokens

apps/web/components/ui/badge.tsx

What Changed

Variant Before (hardcoded) After (semantic)
success bg-emerald-500 text-white bg-success text-success-foreground
warning bg-amber-500 text-white bg-warning text-warning-foreground
info bg-blue-500 text-white bg-info text-info-foreground
active bg-emerald-50 text-emerald-700 border-emerald-200 bg-success/10 text-success border-success/30
draft bg-slate-100 text-slate-600 border-slate-200 bg-muted text-muted-foreground border-border
paused bg-amber-50 text-amber-700 border-amber-200 bg-warning/10 text-warning border-warning/30
The tokens success, warning, info are CSS variables defined in globals.css (both :root and .dark) and mapped in tailwind.config.ts. They automatically adapt to the active theme — no !important hacks needed.

How to Test Badge Changes

Go to Chatbots page. Each chatbot card shows a status badge (Active / Draft / Paused). Check all three look correct.
Click into a chatbot. The header shows the chatbot name + status badge. Verify it matches.
Toggle to Dark Mode (bottom of sidebar). Repeat steps 1-2. Badges should look natural — no washed-out light backgrounds on dark cards.
Go to Settings → Team. The role badges (Org Owner = green tint, Admin = blue tint, Member = outline) should look correct in both themes.

Expected Appearance

Light Mode:

Active Draft Paused Success Warning Info

Dark Mode: Same colors but with opacity-based backgrounds that adapt naturally to the dark background. No white/light patches.

Active badge: subtle green tint bg, green text, thin green border
Draft badge: muted gray bg, gray text, standard border (adapts automatically)
Paused badge: subtle amber tint bg, amber text, thin amber border
Success/Warning/Info: solid filled badges with white text
All badges readable in both light and dark mode

Task 3: Sidebar Dark Mode Hover Colors

apps/web/components/dashboard/Sidebar.tsx

What Changed

Element Before (hardcoded) After (semantic)
Nav link hover hover:bg-emerald-50 hover:text-emerald-700 hover:bg-primary/10 hover:text-primary
Active link shadow shadow-emerald-500/25 shadow-primary/25
Logout text text-red-600 focus:bg-red-50 text-destructive focus:bg-destructive/10
Collapsed logout hover hover:text-red-700 hover:bg-red-50 hover:text-destructive hover:bg-destructive/10
Avatar ring ring-emerald-500/20 ring-primary/20
The brand gradient on the active nav link (from-emerald-600 to-teal-600) and the logo/brand text are intentionally kept as hardcoded brand colors — they work well in both themes since they're medium-saturation colors on both light and dark backgrounds.

How to Test Sidebar Changes

Open the dashboard. The sidebar should show navigation links. Hover over each nav link — you should see a subtle green-tinted background appear with green text.
Switch to Dark Mode (toggle at bottom of sidebar). Hover over nav links again. The hover should show a subtle green tint on the dark background — NOT a washed-out light green patch.
Check the active link (the one matching your current page). It should have a green-to-teal gradient with white text and a subtle colored shadow.
Click your avatar/name area at the bottom → the Logout button in the dropdown should be red-tinted. In dark mode, the red should be the semantic destructive color, not hardcoded red-600.
Collapse the sidebar (click the chevron button at the top). In collapsed mode, the logout icon button at the bottom should also be red/destructive and have a proper hover background in both themes.
Test mobile: Resize browser to <1024px width. The sidebar becomes a slide-out panel. Verify hover colors work in both themes in the mobile overlay as well.

Verification Checklist

Nav link hover: subtle branded green tint (not washed-out) in both themes
Active nav link: gradient looks identical in both themes
Logout dropdown: red text with red-tinted hover in both themes
Collapsed sidebar: logout icon has proper hover in both themes
Avatar ring: subtle ring visible in both themes
Mobile sidebar: all hover colors work correctly
